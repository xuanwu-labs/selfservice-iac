# 03-可观测性集成设计

> 对应 `design.md §04 D41`。承载 OTel 端到端 trace 贯穿的完整集成方案：各层 instrumentation 库、代码片段、trace_id 全链路传递图、metrics 单独走 Prometheus、trace 后端可配置、7 个生产坑清单。

## 0. 目标

- **trace 端到端贯穿**：入口（gin/Connect）→ 业务逻辑 → DB（pgx）→ Redis（若引入）→ 第三方 HTTP → 微服务 RPC → 日志。单一 `trace_id` 全链路传递，无断裂。
- **日志带 trace_id**：每条 zap 日志自动含 `trace_id`/`span_id`（经 otelzap 从 ctx 读取）。
- **metrics 独立**：走 OTel SDK + Prometheus exporter → `/metrics` 端点，Prometheus 抓取，不混入 trace 管线。
- **trace 后端可配置**：env `OTEL_EXPORTER_OTLP_ENDPOINT` 指向 Collector，Collector fan-out 到 Jaeger/Tempo/Datadog。

## 1. 端到端 trace 链路图

```
┌─────────────────────────────────────────────────────────────────────┐
│  外部请求带 W3C traceparent 头                                       │
│  （前端 gRPC-Web / aether CLI / 服务间 gRPC / curl）                     │
└──────────────────────────────┬──────────────────────────────────────┘
                               ▼
┌─────────────────────────────────────────────────────────────────────┐
│  入口层（api/http 或 api/grpc）                                       │
│  gin: otelgin.Middleware("platform")  或  Connect: otelconnect       │
│    ↓ otel.GetTextMapPropagator().Extract() 提取 traceparent          │

└──┬──────────────┬──────────────┬──────────────┬──────────────┬──────┘
   ▼              ▼              ▼              ▼              ▼
┌─────────┐ ┌──────────┐ ┌──────────┐ ┌──────────┐ ┌────────────────┐
│ pgx     │ │ Redis    │ │ HTTP 出站 │ │ Connect  │ │ zap 日志        │

┌─────────────────────────────────────────────────────────────────────┐
```

### 3 个重要纠错（避免踩坑）

1. **`contrib/.../pgx/v5/otelpgx` 不存在**（contrib 所有 pgx 路径 404）→ 用 `github.com/exaring/otelpgx`（事实标准）。
2. **Connect 包是 `connectrpc.com/otelconnect`，不是 `connectrpc.com/otel`**。
3. **Connect 默认不信任远端 trace**（建新 root span 只 Link）→ 内部服务间必须 `WithTrustRemote()`。

## 3. 启动初始化（cmd/server/main.go）

```go
// 1. 设传播器（全局生效，所有 instrumentation 用它）
otel.SetTextMapPropagator(propagation.NewCompositeTextMapPropagator(
    propagation.TraceContext{},
    propagation.Baggage{},
))

// 2. TracerProvider（trace → OTLP → Collector，地址 env 配置）
traceExp, _ := otlptracehttp.New(ctx)  // 读 OTEL_EXPORTER_OTLP_ENDPOINT
tp := sdktrace.NewTracerProvider(
    sdktrace.WithBatcher(traceExp),
    sdktrace.WithResource(resource.NewWithAttributes(
        semconv.SchemaURL,
        semconv.ServiceName("platform"),  // OTEL_SERVICE_NAME env 可覆盖
    )),
)
otel.SetTracerProvider(tp)
defer tp.Shutdown(ctx)  // 关键：刷新最后一批 span

// 3. MeterProvider（metrics → Prometheus exporter → /metrics）
promExp, _ := prometheus.New()  // OTel metric Reader
mp := metric.NewMeterProvider(metric.WithReader(promExp))
otel.SetMeterProvider(mp)
// promExp 的 registry 挂到 gin /metrics 端点

// 4. otelzap（Mode 1：trace_id 入 zap 字段）
logger := otelzap.New(zap.L(),
    otelzap.WithTraceIDField(true),
    otelzap.WithSpanIDField(true),
)
otelzap.ReplaceGlobals(logger)
```

## 4. 各层接入代码片段

### 4.1 gin 入站（otelgin）
```go
r := gin.Default()
r.Use(otelgin.Middleware("platform"))
// handler 里从 c.Request.Context() 取 ctx（span 在里面）
```

### 4.2 Connect 入站 + 出站（otelconnect）
```go
ot, _ := otelconnect.NewInterceptor(otelconnect.WithTrustRemote())  // 内部互信
// 入站 handler：
mux.Handle(svc.NewHandler(impl, connect.WithInterceptors(ot)))
// 出站 client：
client := svc.NewClient(httpClient, baseURL, connect.WithInterceptors(ot))
```

### 4.3 HTTP 出站（otelhttp，调云 API/OIDC/SCM）
```go
client := &http.Client{Transport: otelhttp.NewTransport(http.DefaultTransport)}
req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)  // 必须带 ctx
resp, _ := client.Do(req)  // 自动注入 traceparent 头
```

### 4.4 pgx（otelpgx）
```go
cfg, _ := pgxpool.ParseConfig(dsn)
cfg.ConnConfig.Tracer = otelpgx.NewTracer(otelpgx.WithTrimSQLInSpanName())
pool, _ := pgxpool.NewWithConfig(ctx, cfg)
otelpgx.RecordStats(pool)
// 所有 pool.Query(ctx, ...) 自动成子 span（必须传 ctx）
```

### 4.5 Redis（若引入）
```go
rdb := redis.NewClient(&redis.Options{Addr: addr})
redisotel.InstrumentTracing(rdb)
redisotel.InstrumentMetrics(rdb)
// rdb.Get(ctx, key) 自动成子 span
```

### 4.6 zap 日志带 trace_id（otelzap Mode 1）
```go
// ❌ 错误：裸 zap.L() 读不到 trace（全零）
zap.L().Info("xxx")

// ✅ 正确：传 ctx
otelzap.L().Ctx(ctx).Info("xxx")  // 自动注入 trace_id/span_id 字段
```

## 5. metrics 独立管线（你明确要分离）

```
OTel SDK（MeterProvider）
  ↓ Prometheus exporter（go.opentelemetry.io/otel/exporters/prometheus）
/metrics 端点（gin 挂载）
  ↓ Prometheus / VictoriaMetrics 抓取（pull）
```

**与 trace 管线解耦**：trace 走 OTLP → Collector；metrics 走 Prometheus scrape。两条独立路径，互不干扰。

## 6. trace 后端可配置

```
env OTEL_EXPORTER_OTLP_ENDPOINT=http://otelcol:4318
  ↓ app 读 env（otlptracehttp 自动）
OTLP/HTTP → Collector（4318）
  ↓ Collector fan-out
Jaeger / Tempo / Datadog（后端可换，app 不感知）
```

**为什么经 Collector**：批处理 + 重试 + 尾部采样 + 解耦 app 与后端。直接 app→后端也行（dev），但生产建议 Collector。

## 7. 7 个生产坑清单（必读）

1. **忘记 `otel.SetTextMapPropagator(TraceContext{})`** → 所有 hop 都是新 root trace，跨进程完全断。
2. **pgx/Redis/HTTP/Connect 调用传 `context.Background()`** → trace 在该层断。**必须传请求 ctx**。
3. **Connect 服务端没开 `WithTrustRemote()`** → 内部 RPC 建新 top-level trace，不延续。
4. **裸 `zap.L()` 不传 ctx** → trace_id 全零（#6114 症状）。用 `otelzap.L().Ctx(ctx).Info(...)`。
5. **没调 `tp.Shutdown(ctx)` 退出** → 最后一批 span 丢失。
6. **gin 里读错 context** → span 在 `c.Request.Context()`，不是 `c.MustGet()`。
7. **用废弃的 otelgrpc 拦截器** → 有内存耗尽 CVE；用 `NewClientHandler`/`NewServerHandler` StatsHandler API。
8. **River worker 的 ctx 不带入队时的 trace** → River job handler 拿到的 ctx 是 River 新建的（不含入队时的 span），工单全链路在 worker 边界断裂。**解法**：`core/queue/` 封装 `TracedInsert`（入队时把 traceparent 序列化进 job metadata）+ `TracedWorker` base（取出后 `propagator.Extract` 恢复 ctx 再 `tracer.Start`），所有 job handler 强制继承。

## 8. 验证标准

- [ ] 一个请求从 gin 入站到 pgx 查询到 HTTP 出站，在 Jaeger/Tempo 看到完整 span 树（同一 trace_id）。
- [ ] 每条 zap 日志含非零 `trace_id`（grep 日志按 trace_id 能串起一整个请求的所有日志）。
- [ ] `/metrics` 端点暴露 Prometheus 格式指标，Prometheus 能抓取。
- [ ] 改 `OTEL_EXPORTER_OTLP_ENDPOINT` env 能切换 trace 后端，app 代码零改动。
