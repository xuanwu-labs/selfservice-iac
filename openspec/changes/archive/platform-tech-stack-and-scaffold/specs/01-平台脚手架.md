# 01-平台脚手架（platform-scaffold）

能力 ID：`platform-scaffold`
覆盖：`server/` Go module 的最小可编译目录骨架 + Makefile + go.mod + 一个端到端可跑的"build → test → migrate Up/Down"链路。为 `iac-self-service-platform` 的全部 209 个实现 task 提供确定的地基。

## ADDED Requirements

### Requirement: 三层模型分离
平台 SHALL 将三种模型分开存放：Entity（数据模型，对应 DB 表）放 `internal/model/entity/`；DTO/Proto Message（传输模型，proto 生成）放 `internal/proto/`；Domain Object（领域对象，含业务方法）放 `core/<domain>/`。entity ↔ proto message 的转换放 `internal/mapping/`。sqlc 自动生成的 model struct 归 `pkg/db/generated/`。

#### Scenario: entity 和 proto message 分离
- **WHEN** DB 表有敏感字段（如 `password_hash`）
- **THEN** entity（`internal/model/entity/`）含该字段，但 proto message（`internal/proto/`）不含，API 响应不泄露敏感字段

### Requirement: 领域核心顶层分层（package-by-feature）
平台 SHALL 采用领域核心顶层分层：领域核心 `core/` 是顶层一等公民（package-by-feature），`api/` 放传输 handler（http/grpc），`data/` 放数据访问，`internal/` 只装私有基建（config/otel/model/proto/errors 等，不套微服务封装）。业务逻辑（registry/codegen/orchestrator 等）放 `core/` 而非 `internal/`。

#### Scenario: 领域核心顶层可见
- **WHEN** 新贡献者打开 `server/` 目录
- **THEN** `core/` 顶层可见，其下按业务能力分子包（core/codegen, core/orchestrator），系统领域心脏一眼可识别，而非埋在 internal/ 里

#### Scenario: internal 只装私有基建
- **WHEN** 审查 `internal/` 目录
- **THEN** 只含 micro/（微服务基建）、model/、proto/（生成代码）、errors/、observability/ 等不外露的基础设施，无业务逻辑

### Requirement: 可编译的目录骨架
平台 SHALL 提供一个独立 Go module `server/`，包含 `cmd/{platform,aether,migrate}/`、`api/{http,grpc,proto}/`、`core/`（领域核心顶层）、`data/`、`internal/{micro,model/entity,proto,errors,...}/`、`pkg/db/{queries,generated}/`、`db/migrations/`，且 `go build ./...` 通过。

#### Scenario: 全量构建通过
- **WHEN** 在 `server/` 下执行 `go build ./...`
- **THEN** 退出码 0，无编译错误，`cmd/server`、`cmd/aether`、`cmd/migrate` 三个二进制可生成

### Requirement: 端到端链路可跑
平台 SHALL 提供一个 Makefile，目标 `build`/`test`/`lint`/`migrate-up`/`migrate-down`/`sqlc-gen` 全部可执行且全绿。

#### Scenario: make build && make test 全绿
- **WHEN** 在 `server/` 下执行 `make build && make test`
- **THEN** 退出码 0，所有单元测试通过，三个二进制生成

#### Scenario: 迁移 Up/Down 幂等
- **WHEN** 在 `server/` 下依次执行 `make migrate-up && make migrate-down && make migrate-up`
- **THEN** 退出码 0，001_init 迁移后 teams 表存在，Down 后 teams 表不存在，再次 Up 后恢复

### Requirement: D1 边界由 lint 强制
平台 SHALL 通过 `.golangci.yml` 的 depguard 规则，禁止 `server/**` import `github.com/terramate-io/terramate/<protected>` 内部包，把 D1 的"exec 解耦"变成 CI 硬门。

#### Scenario: depguard 拦截违规 import
- **WHEN** 一个 `_probe/import_violation.go` 文件 import `github.com/terramate-io/terramate/stack`
- **THEN** `make lint` 报错，depguard 输出违规规则名 + 文件路径，退出码非 0

#### Scenario: 合规代码 lint 通过
- **WHEN** `server/**` 全部代码只通过 exec 调用 terramate（无内部包 import）
- **THEN** `make lint` 退出码 0
