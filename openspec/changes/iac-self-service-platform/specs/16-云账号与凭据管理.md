# 07-云账号与凭据管理（cloud-credentials）

能力 ID：`cloud-credentials`
覆盖：云账号纳管、团队↔云账号授权（申请过滤）、三层凭据模型（bootstrap/执行/个人）、OIDC 联邦优先、凭据注入 Executor（不入 git/日志）、IAM 角色模板化、凭据生命周期与轮换、申请时可见性控制。

> 关联：specs/11（Executor 沙箱执行）、specs/06（编排引擎在 plan/apply 时注入）、specs/02（catalog 申请入口按 grant 过滤）、specs/09（身份与组织）、specs/08（RBAC + 审计）、specs/10（OPA 二次校验）。对应 design `D23`、`docs/06-云账号与凭据管理`。

## ADDED Requirements

### Requirement: 云账号纳管
平台 SHALL 纳管云账号（`cloud_accounts`：provider=alicloud/aws/azure、account_id、别名、region 默认、是否启用 OIDC trust、关联 bootstrap 凭据引用）；bootstrap 凭据（每云账号 1 套，用于开通/IAM 配置/读账单/建子角色）MUST 标记为 vault 级，**强制双人审批 + 周期轮换 + 全审计**。

#### Scenario: 注册云账号并配 bootstrap 凭据
- **WHEN** 平台运维注册阿里云账号 `corp-prod-1`
- **THEN** 平台记录 account_id/region/别名，bootstrap 凭据密文存 secret store（DB 仅存引用），要求至少 2 名守护人确认，操作入审计日志

#### Scenario: bootstrap 凭据双人审批轮换
- **WHEN** bootstrap AK/SK 到达轮换窗口或运维发起轮换
- **THEN** 平台发起双人审批流，2 名守护人确认后才执行轮换，旧凭据立即吊销，全程审计

### Requirement: 团队↔云账号授权（申请过滤）
平台 SHALL 用 `team_cloud_grants(team_id, cloud_account_id, allowed_layers, iam_role_template, budget_quota, expires_at)` 显式声明"哪个团队可在哪个云账号下申请哪些层的资源"；申请入口 `GET /catalog` MUST 按调用者团队 join 此表过滤——**只展示该团队被授权的云账号 + catalog 项**，未授权的云厂商/账号 MUST NOT 出现在申请表单的"目标云"下拉。

#### Scenario: 申请入口按授权过滤云账号
- **WHEN** 业务 A 团队成员进入"新建申请"
- **THEN** 平台 join `team_cloud_grants` 返回该团队被授权的云账号列表（如 alicloud `corp-prod-1`），未授权的 aws 账号 `corp-prod-2` **不出现**在"目标云"下拉

#### Scenario: 未授权团队申请被拒
- **WHEN** 业务 A 团队尝试申请 `aws/corp-prod-2` 的 RDS（无 grant）
- **THEN** API 返回 403 并提示"团队未授权在该云账号下申请资源"

#### Scenario: 授权过期自动失效
- **WHEN** 某 `team_cloud_grants.expires_at` 已过期
- **THEN** 该授权停止生效，相关云账号从该团队申请下拉移除，FinOps/CMDB 现存资源不受影响（只阻断新申请）

### Requirement: 三层凭据模型
平台 SHALL 按作用域 + 风险维护三层凭据：①**Bootstrap/Admin**（每云账号 1 套，vault 级，双人审批 + 轮换）；②**执行凭据**（per-team/per-bundle × per-cloud_account，平台代跑 terraform 时 assume 的 IAM 身份，**OIDC 联邦优先**无长存 AK/SK，fallback 长 AK/SK 强制轮换）；③**个人**（仅 RBAC 身份，**MUST NOT 持有执行云凭据**——平台执行而非人手执行）。

#### Scenario: 个人申请不持有云凭据
- **WHEN** 任意用户提交 RDS 申请
- **THEN** 平台用该团队的**执行凭据**（OIDC 短期或长 AK/SK）代跑 terraform，**不发放任何云 AK/SK 给个人**；个人身份仅用于 RBAC + 审批 + 审计

#### Scenario: per-team 而非 per-person
- **WHEN** 同一团队 5 名成员交替提交申请
- **THEN** 5 次执行均使用**同一组团队执行凭据**，日志按 team+bundle 归集，个人身份只记录在 `request.created_by` 用于审计，不参与云凭据选择

### Requirement: OIDC 联邦优先（无长期凭据）
平台 SHALL 作为云账号的 Trusted OIDC Issuer（每云账号配 `oidc:<platform>/assume-role/<team>` trust policy）；Executor 执行时拿平台内部 short-lived token 换云 STS（aws `AssumeRoleWithWebIdentity` / alicloud `AssumeRoleWithOIDC`），**零长期凭据、按需签发、自然过期**；长存 AK/SK 仅在云不支持 OIDC 或离线场景作 fallback，且 MUST 强制周期轮换。

#### Scenario: OIDC 路径执行 plan
- **WHEN** DBA 团队提交 RDS 申请，DBA 团队在该云账号下配了 OIDC trust
- **THEN** Executor.Run 拿平台 OIDC token → AssumeRole `TmExec-DBA-RDS` → 拿到 1h STS → 注入 env → 跑 plan；执行结束 STS 自然过期，**全程无 AK/SK 落盘**

#### Scenario: 长存 AK/SK fallback
- **WHEN** 某私有云不支持 OIDC
- **THEN** 平台 fallback 到该团队的长期 AK/SK（标记 `credential_type=long_lived`），MUST 强制 90 天轮换 + 泄漏紧急轮换 + 注入仍只在 Executor 单次 Run 内

### Requirement: 凭据注入 Executor（不入 git/日志/codegen）
平台 SHALL 在 Executor.Run 执行时按 `(team, cloud_account, catalog_item)` 解析所需凭据并注入子进程/容器 env（`AWS_ACCESS_KEY_ID`/`AWS_SECRET_ACCESS_KEY`/`AWS_SESSION_TOKEN` 或 `AWS_WEB_IDENTITY_TOKEN_FILE` 等），**绝不写入 worktree/git/codegen 或日志**；codegen 阶段对敏感字段用占位符（如 `__TM_SECRET_*__`），运行期由 Executor 填充；日志 MUST 脱敏（正则屏蔽 AK 形态 + 已知 secret 哈希替换）。

#### Scenario: 敏感字段占位符填充
- **WHEN** codegen 生成含 secret 的 stack 配置
- **THEN** staging 写入占位符 `__TM_SECRET_AWS_ACCESS_KEY_ID__`，**不写真值**；Executor.Run 解析占位符并注入子进程 env，worktree/git 中始终只有占位符

#### Scenario: 日志脱敏
- **WHEN** terraform 输出含 AK 形态字符串（如 `AKIAIOSF...`）
- **THEN** 平台日志管道正则替换为 `***REDACTED-AK***` 后才写入 `request_events`，原始值不入库不入审计

#### Scenario: 凭据不出现在 git
- **WHEN** 任何代码生成产物被提交到工作仓库
- **THEN** 提交内容 MUST NOT 含明文凭据（含占位符除外），CI 跑 secret scanning 兜底

### Requirement: IAM 角色与权限模板化
平台 SHALL 让 catalog 项声明 `required_permissions`（如 `dba/rds` 声明 `alicloud:rds:*` + `vpc:DescribeVSwitches`）；平台 bootstrap 凭据为每团队在云账号内 provision 标准 IAM 角色（`TmExec-<Team>-<Capability>`），角色策略由 catalog `required_permissions` 聚合生成（**最小权限**）；执行凭据 assume 匹配角色，OPA 二次校验"申请项 ↔ 角色权限"一致，不匹配 MUST 阻断。

#### Scenario: catalog 声明 required_permissions
- **WHEN** 注册 `dba/rds` 模块到 catalog
- **THEN** 模块声明 `required_permissions=[alicloud:rds:*, alicloud:vpc:DescribeVSwitches]`，平台聚合生成/更新 IAM 角色策略 `TmExec-DBA-RDS`

#### Scenario: 申请项与角色权限匹配校验
- **WHEN** DBA 团队申请 `dba/rds`，但 DBA 团队执行角色缺 `rds:CreateDBInstance`
- **THEN** OPA 校验失败，平台阻断执行并提示"团队执行角色缺少 rds:CreateDBInstance 权限，联系平台运维"

### Requirement: 凭据生命周期与轮换
平台 SHALL 管理凭据全生命周期：①OIDC ephemeral 无需轮换（按需签发自然过期，撤 trust policy 即停）；②长期执行 AK/SK **强制周期轮换**（默认 90 天，可配）+ 泄漏紧急轮换；③Bootstrap Admin 双人审批轮换 + 全审计；平台 MUST 定期扫描过期/将过期凭据告警运维，并跑泄漏检测（日志 + secret scanning）触发强制轮换。

#### Scenario: 长存凭据到期告警
- **WHEN** 某长期执行 AK/SK 距过期 < 7 天
- **THEN** 平台告警平台运维 + 团队 owner，未及时轮换到期后凭据自动吊销（阻断执行）

#### Scenario: 泄漏紧急轮换
- **WHEN** secret scanning 在日志/git 中检测到某执行凭据明文
- **THEN** 平台立即吊销该凭据 + 强制轮换 + 全审计 + 通知运维，相关工单暂停重试

### Requirement: 云账号与凭据管理界面
平台 SHALL 提供"云账号与凭据"管理页：①云账号清单（provider/account_id/别名/region/OIDC 状态/bootstrap 状态）；②团队授权矩阵（team × cloud_account × allowed_layers × iam_role_template × 配额 × 过期）；③凭据列表（类型/作用域/状态/轮换窗口/守护人，**密文永不回显**）；④OIDC trust 与 IAM 角色配置入口；⑤申请页"目标云"下拉按调用者团队 grant 动态过滤。所有写操作 MUST 走 RBAC + 审计。

#### Scenario: 运维查看凭据列表
- **WHEN** 平台运维打开凭据列表
- **THEN** 看到每条凭据的元数据（类型/作用域/状态/轮换窗口/守护人），**明文 NEVER 回显**（仅显示 masked 占位 + "测试连接"按钮）

#### Scenario: 申请页目标云按授权过滤
- **WHEN** 业务 A 用户进入新建申请页
- **THEN** "目标云"下拉只列该团队被授权的云账号，无授权的灰化或不出现，鼠标悬停提示"团队未授权，联系平台运维"
