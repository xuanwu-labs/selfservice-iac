# 02-服务目录（service-catalog）

能力 ID：`service-catalog`
覆盖：把原子模块抽象为简洁的申请表单，其余变量由平台以最佳实践默认值自动填充。

## ADDED Requirements

### Requirement: 发布目录项
平台 SHALL 允许管理员把一个已校验通过的原子模块发布为"服务目录项"，绑定一个表单 schema 与归属团队 / 分层。

#### Scenario: 发布 RDS 申请目录项
- **WHEN** DBA 管理员把模块 `dba/rds@v1.2.0` 发布为目录项"申请 RDS 实例"
- **THEN** 该目录项出现在授权用户的目录视图中，表单仅暴露 `instance_type`、`storage_size` 等必填项

### Requirement: 表单 schema 生成
平台 SHALL 基于模块变量契约生成表单 schema，管理员可从变量中挑选"对用户可见的字段"，其余字段由平台默认值填充，MUST 支持必填 / 选填 / 枚举 / 范围约束。

#### Scenario: 隐藏内部变量并注入默认值
- **WHEN** RDS 模块有 30 个变量，管理员仅把 `instance_type`、`storage_size` 标记为"用户可见"
- **THEN** 申请表单只显示这 2 个字段；其余 28 个变量在生成代码时由平台注入最佳实践默认值，用户不可见

#### Scenario: 枚举约束
- **WHEN** `instance_type` 配置允许值为 `mysql.n2.medium.1c`、`mysql.n2.large.1c`
- **THEN** 表单渲染为下拉选择，用户无法填写枚举外的值

### Requirement: 最佳实践默认值
平台 SHALL 为每个目录项维护一份"最佳实践默认值覆盖"，覆盖模块自带默认值，用于强制合规（如安全组最小开放、备份必须开启），生成的代码 MUST 应用这些覆盖。

#### Scenario: 强制开启备份
- **WHEN** 模块默认 `backup_retention=0`，平台最佳实践覆盖为 `7`
- **THEN** 生成的 Terraform 代码中 `backup_retention = 7`，用户无权改回 0

### Requirement: 目录可见性控制
平台 SHALL 按"归属团队 / 分层 / 目标受众"控制目录项的可见性，确保业务团队只看到可自助申请的项，全局 / 共享类目录项仅对应治理团队可见。

#### Scenario: 业务团队视角
- **WHEN** 业务团队用户打开服务目录
- **THEN** 仅显示 Application 层与其被授权申请的 Middleware 层目录项（如"申请数据库账号"），不显示 VPC 等全局项

### Requirement: 目录项版本与变更影响
平台 SHALL 在目录项引用的模块版本变更时，提示影响范围（哪些已创建资源引用了旧版本），并要求管理员确认推广策略，MUST NOT 静默变更已部署资源。

#### Scenario: 模块升级提示影响范围
- **WHEN** 目录项关联的模块从 `v1.2.0` 升级到 `v1.3.0`
- **THEN** 平台列出所有引用该目录项的部署单元，要求管理员选择"仅新申请使用 / 逐步推广"，不自动变更存量资源

### Requirement: catalog 默认 tag 与用户 tag 白名单（D28）
catalog 项 SHALL 含 `default_tags_json`（catalog 注册者声明的默认 tag，如 `{"app":"order-service"}`，D28 L6 层）与 `user_allowed_tag_keys_json`（用户表单可加的自定义 tag key 白名单）。`user_allowed_tag_keys_json` 空数组 `[]` 表示用户不能加任何自定义 tag（默认）；非空时仅允许列出的 key。

#### Scenario: catalog 默认 tag 注入
- **WHEN** catalog 项 default_tags_json={"app":"order-service"}，用户提交申请
- **THEN** codegen MUST 在生成的 module 调用中包含 `app=order-service` tag（L6 层）；用户可在白名单内追加但不可移除

#### Scenario: 用户 tag 超白名单拒绝
- **WHEN** catalog 项 user_allowed_tag_keys_json=["owner","ticket"]，用户表单 tags 含 `secret-key`
- **THEN** 平台 codegen S8 阶段校验失败，返回 422 + `{"error":"tag_key_not_allowed","key":"secret-key","allowed":["owner","ticket"]}`

#### Scenario: 默认白名单空（最严格）
- **WHEN** catalog 项 user_allowed_tag_keys_json=[]，用户表单提交任何自定义 tag
- **THEN** 平台拒绝（白名单外）；catalog 注册者 MUST 显式声明白名单才能开放用户 tag

### Requirement: catalog 项生命周期（sunset 三态机，L5）
catalog 项 SHALL 有 `status` 字段，三态生命周期：`active`（正常申请）→ `deprecated`（禁新申请，已创建 stack 可继续 plan/apply）→ `archived`（拒引用，已创建 stack 标需迁移）。管理员操作 sunset 时 MUST 指定 `replacement_catalog_item_id`（替代项），平台在拒绝引用时提示用户迁移到替代项。

#### Scenario: deprecated 禁新申请
- **WHEN** 管理员将 catalog 项 `dba/rds` 标 `deprecated`，设定替代项 `dba/rds-v2`
- **THEN** 申请页隐藏 `dba/rds`；已创建的 stack 仍可 plan/apply（存量不受影响）

#### Scenario: archived 拒引用
- **WHEN** catalog 项 `dba/rds` 标 `archived`，用户尝试申请新 stack
- **THEN** 平台拒绝，返回 `{"error":"catalog_archived","item":"dba/rds","replacement":"dba/rds-v2","message":"请迁移到替代项"}`
