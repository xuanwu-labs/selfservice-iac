# 09-状态与漂移（state-drift）

能力 ID：`state-drift`
覆盖：Terraform 远程 backend 约定、周期性漂移检测（开源 Terramate 无此引擎，由平台自研）、漂移事件与同步策略。

## ADDED Requirements

### Requirement: 远程 backend 约定
平台 SHALL 强制所有 stack 使用远程 backend（S3 / MinIO 兼容 + 锁），每个 stack 一个独立 state key，state key 由 stack 路径确定性推导；MUST NOT 允许 local backend 进入生产。

#### Scenario: 每 stack 独立 state key
- **WHEN** 生成 `application/platform-default/team-a/orders/rds-prod` stack
- **THEN** 生成的 `backend.tf` 指向统一远程 backend，key 为 `application/platform-default/team-a/orders/rds-prod`，与同名 stack 一一对应

#### Scenario: 禁用 local backend
- **WHEN** 生成的代码使用 `backend "local"`
- **THEN** 平台校验拒绝，提示必须使用远程 backend

### Requirement: 周期性漂移检测
平台 SHALL 提供独立的漂移检测器，按调度对每个 stack 执行 `terraform plan`（只读），比对真实云与期望状态的差异；由于开源 Terramate 不含漂移引擎，该能力 MUST 由平台自研实现。漂移检测的只读 plan SHALL 通过与编排流水线相同的 `Executor` 接口执行（specs/11 D20），复用同一 worktree 治理（D4）、工具链与隔离契约，MUST NOT 为漂移另造执行路径。

#### Scenario: 漂移检测复用执行沙箱
- **WHEN** 漂移检测器对某 stack 触发只读 plan
- **THEN** 平台经 `Executor`（process/container/kubernetes/remote 之一）申请只读 worktree（pinned_commit）并执行 `terraform plan -detailed-exitcode`，退出码 2=漂移，与工单 plan 走同一沙箱同一工具链

#### Scenario: 检测到手工改动
- **WHEN** 有人手工在云控制台修改了 RDS 实例规格，平台漂移检测器对该 stack 运行 `plan`
- **THEN** 平台识别到漂移（规格不一致），生成漂移记录，状态 `drifted`

#### Scenario: 无漂移
- **WHEN** 漂移检测器运行 plan，退出码 0 且无变更
- **THEN** 平台更新 stack 健康度为 `in-sync`，不产生漂移记录

### Requirement: 漂移事件通知
平台 SHALL 在发现漂移时发布 `drift.detected` 事件，并在界面以醒目方式通知资源归属团队与相关用户，MUST 包含差异摘要。

#### Scenario: 通知 DBA 发现 RDS 漂移
- **WHEN** `rds-orders-prod` 检测到漂移
- **THEN** 平台通知 DBA 团队，消息含差异摘要（如"规格由 mysql.n2.medium.1c 变为 mysql.n2.large.1c"），并提供"查看详情 / 处理"入口

### Requirement: 同步策略确认
平台 SHALL 要求人工对漂移做出处置决策，提供两种同步策略：`采用云端状态`（反向 import 真实状态）或 `恢复期望状态`（apply 把云改回去）；MUST NOT 自动处置漂移。

#### Scenario: 用户选择采用云端状态
- **WHEN** DBA 对漂移选择"采用云端状态"
- **THEN** 平台生成对应的 `terraform import` / state 调整任务并执行，使 state 与云一致，关闭漂移记录

#### Scenario: 用户选择恢复期望状态
- **WHEN** DBA 选择"恢复期望状态"
- **THEN** 平台触发 `terramate run ... apply`，把云资源改回期望配置，完成后关闭漂移记录

### Requirement: 漂移检测调度与限流
平台 SHALL 支持按分层 / 团队 / stack 配置漂移检测频率与时间窗，并对并发 plan 做限流，避免后端被打满。

#### Scenario: Global 层低频检测
- **WHEN** Global 层 stack 配置为每日检测一次
- **THEN** 检测器按调度执行，不在高峰窗口并发运行多个 Global stack plan

#### Scenario: 迁移批次自动静默（D26 衔接）
- **WHEN** 某 stack 进入 layer 规则迁移批次（QuiesceMode，见 specs/04 D26），可能产生 state mv 期间的短暂 plan 差异
- **THEN** 漂移检测器 MUST 自动静默该批 stack（不产生漂移记录、不告警），静默期计入迁移窗口；迁移批次完成后（stacks 升到新版本或回滚结束），漂移检测自动恢复，并触发一次 on-demand 对账确认 zero-diff；MUST NOT 在迁移期全局暂停漂移检测（其他非迁移 stack 照常检测）
