# 14-存量导入（legacy-import）

能力 ID：`legacy-import`
覆盖：把云上存量资源（手工创建或别处管理）纳入平台治理，基于 Terraform 1.5+ 声明式 import 块。

## ADDED Requirements

### Requirement: 存量导入向导
平台 SHALL 提供向导：选目录项/模块 → 输入云端资源 ID → 平台生成声明式 `import` 块 + module 调用骨架 → 执行 import → plan 验证 → 纳管；全过程 MUST 走工单留审批与审计。

导入完成后 MUST 进入显式生命周期：`discovered → candidate → imported-limited → managed-readonly → managed-changeable → standard`。非标准存量默认落到 `managed-readonly`，平台先提供 CMDB、漂移、成本归属等可观测能力，禁止自动 apply；只有人工 review、敏感字段处理、tag/owner/依赖图补齐并通过零变更 plan 后，才能进入 `managed-changeable`。

#### Scenario: 导入一台存量 RDS
- **WHEN** DBA 选 `dba/rds` 模块，输入资源 ID `rm-bp1xxxxxxx`
- **THEN** 平台生成 `import { to = module.rds.alicloud_db_instance.this; id = "rm-bp1xxxxxxx" }` 与 module 调用骨架，触发 import 工单

### Requirement: 自动生成配置（generate-config-out）
平台 SHALL 用 `terraform plan -generate-config-out=generated.tf` 自动生成资源配置，生成后 MUST 标记为"待 review"（敏感默认值、冗余字段需人工清理），review 通过才可纳管。

#### Scenario: 生成并清理配置
- **WHEN** import 落 state 后执行 `plan -generate-config-out`
- **THEN** 生成 `generated.tf`，平台标记待 review；管理员清理（如移除明文密码、归整字段）后提交

### Requirement: plan 验证零变更
import 完成后，平台 SHALL 强制 `terraform plan` 显示 `0 to add, 0 to change, 0 to destroy`，否则视为代码与存量不一致，MUST NOT 完成纳管。

#### Scenario: 代码与存量不一致
- **WHEN** import 后 plan 显示有变更
- **THEN** 平台阻断进入 `managed-changeable`，保留 `managed-readonly` 或 `imported-limited` 状态，提示"生成代码与云端实际存在差异：xxx"，要求人工调整模块调用或变量

### Requirement: 批量导入
平台 SHALL 支持 `for_each` 批量导入同类资源（一组资源 ID → 一组 import 块），MUST 提供批量录入与进度跟踪。

#### Scenario: 批量导入 10 台 ECS
- **WHEN** 管理员录入 10 个 ECS 实例 ID
- **THEN** 平台生成带 `for_each` 的 import 块，批量 import，逐台报告成功/失败

### Requirement: 不支持 import 的资源处理
当 provider 资源不支持 `import` 时，平台 SHALL 标记为 `limited`，提供半自动流程（手工 state 编辑 + 占位配置），MUST 明确告知限制。

#### Scenario: 资源不支持 import
- **WHEN** 某资源类型 provider 不支持 import
- **THEN** 平台向导提示"该资源不支持自动 import，进入 limited 流程"，提供 state 手工编辑指引，标记为受限纳管（漂移检测仍生效但 apply 受限）

#### Scenario: read-only 过渡
- **WHEN** 存量资源已 import 但缺标准 tag 或 owner 未补齐
- **THEN** 平台将 stack 标记为 `managed-readonly`，允许漂移检测和 CMDB 查询，禁止平台自动 apply，并生成 `manual_intervention_tasks` 要求 owner 补齐治理信息

### Requirement: 敏感字段处理
import 无法读取的敏感字段（密码、token）SHALL 留空并标记 `sensitive` 待用户补填，平台 MUST NOT 猜测或填充。

#### Scenario: RDS 密码留空
- **WHEN** import RDS 后 `root_password` 不可读
- **THEN** 生成的配置中该字段留空标记 sensitive，工单提示用户补填，补填前 apply 受限
