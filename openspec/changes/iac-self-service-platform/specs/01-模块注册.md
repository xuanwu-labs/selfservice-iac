# 01-模块注册（module-registry）

能力 ID：`module-registry`
覆盖：把 Git 上已有的原子 Terraform 模块注册进平台，做版本管理与变量契约提取，供服务目录引用。

## ADDED Requirements

### Requirement: 注册 Git 原子模块
平台 SHALL 允许管理员将一个 Git 上的 Terraform 模块注册为"原子模块"，登记其源地址、命名空间、归属团队与所属分层（Global / Middleware / Application）。

#### Scenario: 注册一个新的 RDS 模块
- **WHEN** 管理员提交模块源 `git::https://github.com/org/terraform-alicloud-rds@ref=v1.2.0`、命名空间 `dba/rds`、归属团队 `DBA`、分层 `Middleware`
- **THEN** 平台持久化该模块记录，状态置为 `pending-validation`，并触发契约提取与校验

#### Scenario: 重复注册相同源与版本
- **WHEN** 管理员再次注册已存在的相同 `源@ref`
- **THEN** 平台拒绝注册并返回明确的"已存在"错误，不产生重复记录

### Requirement: 模块版本管理
平台 SHALL 支持以 tag / branch / commit ref 锁定模块版本，并能在引用新 ref 时记录版本变更。

#### Scenario: 模块升级到新 tag
- **WHEN** 管理员把模块 `dba/rds` 的 ref 从 `v1.2.0` 升到 `v1.3.0`
- **THEN** 平台保存新版本记录，标记旧版本为 `superseded`，已引用旧版本的服务目录项不自动变更（保持可预测）

### Requirement: 变量契约提取
平台 SHALL 在注册时拉取模块，解析其 `variables.tf`，提取每个变量的名称、类型、描述、默认值与是否敏感，生成结构化变量契约，作为表单 schema 的来源。

#### Scenario: 提取 RDS 模块变量契约
- **WHEN** 平台校验 `dba/rds@v1.2.0` 成功
- **THEN** 生成契约包含 `instance_type`（string，必填）、`storage_size`（number，必填）、`backup_retention`（number，默认 7）、`root_password`（string，sensitive）

#### Scenario: 模块缺少 variables.tf
- **WHEN** 被注册模块不存在 `variables.tf`
- **THEN** 平台标记校验失败，错误信息指出"缺失变量定义"，模块不可发布到服务目录

### Requirement: 模块可 plan 校验
平台 SHALL 在注册时对模块执行最小化的 `terraform validate`（必要时 `init`），确保模块可用，校验失败的模块 SHALL NOT 可被发布到服务目录。

#### Scenario: 模块语法错误
- **WHEN** 注册的模块 `terraform validate` 失败
- **THEN** 平台将模块状态置为 `validation-failed`，记录错误日志，禁止发布

### Requirement: 模块归属与可见性
平台 SHALL 记录每个原子模块的归属团队，并允许按团队 / 分层控制其后续在服务目录中的可见范围。

#### Scenario: 网络模块仅平台运维可见
- **WHEN** 模块归属 `platform-networking` 团队、分层 `Global`
- **THEN** 该模块默认仅对 `平台运维` 团队可见，业务团队在服务目录中不可见
