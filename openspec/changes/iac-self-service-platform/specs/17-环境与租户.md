# 08-环境与租户（environment-and-tenant）

能力 ID：`environment-and-tenant`
覆盖：Environment / Tenant / EnvironmentTenantBinding 三表的 CRUD + 网络绑定解析 + env 维度授权。对应 design `D27`、`docs/07-环境与租户网络模型`。

## ADDED Requirements

### Requirement: Environment 一等对象
平台 SHALL 把 Environment（dev/staging/prod/dr）作为一等治理对象存储于 `environments` 表，每个 env MUST 含 `env_logical_id`（稳定身份）+ `stage`（治理强度分级）+ `cloud_account_id` + `region` + `tag_namespace_json` + `network_topology`。`stacks.env` 字段 SHALL 作为反规范化便利保留，权威以 `environments` 表为准。

#### Scenario: 创建 env
- **WHEN** 平台运维通过"环境管理"向导提交 env_logical_id=prod + stage=prod + cloud_account_id=alicloud-corp-prod + region=cn-hangzhou + tag_namespace_json={"env":"prod","cost-center":"CC-P-01"}
- **THEN** 平台在 `environments` 表落库，UNIQUE 约束校验 `env_logical_id`，UI 在"环境管理"页显示该 env 卡片

#### Scenario: stage 决定治理强度
- **WHEN** 同一 catalog 项（如 dba/rds）在 env=dev 与 env=prod 提交申请
- **THEN** 平台依据 `environments.stage` 字段路由：dev 自动放行（OPA 低风险规则）/ prod 强制 DBA 审批 + 双签

### Requirement: Tenant 一等对象 + isolation_level 仅 2 档
平台 SHALL 把 Tenant 作为一等对象存储于 `tenants` 表，默认存在 `platform-default` 单租户。`tenants.isolation_level` MUST 为 `vpc-per-env`（默认）或 `account-per-env`（escape hatch），不允许其他值。

#### Scenario: 默认 platform-default 租户
- **WHEN** 平台首次初始化
- **THEN** 自动创建 `tenants(tenant_logical_id='platform-default', isolation_level='vpc-per-env', kind='internal')`，所有未显式指定 tenant 的工单/stack 默认归属此租户

#### Scenario: 创建外部客户租户（vpc-per-env）
- **WHEN** 平台运维创建 tenant_logical_id=corp-a + isolation_level=vpc-per-env + kind=external
- **THEN** 平台落库，UI 入"租户管理"页；后续 corp-a 工单全部绑定此 tenant_id，独立 VPC（D27 §3）

#### Scenario: 创建强合规租户（account-per-env）
- **WHEN** 金融业务需要硬隔离，平台运维创建 tenant_logical_id=bank-finance + isolation_level=account-per-env
- **THEN** 平台落库；该租户的 environment_tenant_bindings MUST 填 `override_cloud_account_id`，与 `environments.cloud_account_id` 不同

#### Scenario: 拒绝非法 isolation_level
- **WHEN** 提交 isolation_level=shared-vpc（已废弃档）
- **THEN** 平台返回 400 + `{"error":"isolation_level_invalid","allowed":["vpc-per-env","account-per-env"],"reason":"shared-vpc mode deprecated in D27"}`

### Requirement: EnvironmentTenantBinding 三元组（codegen Stage 4 查询入口）
平台 SHALL 用 `environment_tenant_bindings` 表存储 (env_id, tenant_id, layer_logical_id) 三元组到网络资源的映射，UNIQUE 约束 `(env_id, tenant_id, layer_logical_id)`。binding MUST 含 `vpc_stack_id`（引用 Global 层 VPC stack）+ `subnet_blocks_json` + `security_group_base_id`。account-per-env 模式 MUST 额外填 `override_cloud_account_id`。

#### Scenario: codegen Stage 4 解析 binding
- **WHEN** 工单 (env=prod, tenant=corp-a, layer=Application) 进入 codegen Stage 4
- **THEN** 平台查 `environment_tenant_bindings WHERE env_id=prod AND tenant_id=corp-a AND layer_logical_id=Application`，把 vpc_id + subnet_ids 注入 Terraform 变量，resolved_params_json 记 `source=env_context, rank=6`

#### Scenario: Application 层缺 binding 拒绝
- **WHEN** 工单 (env=prod, tenant=corp-a, layer=Application) 但 environment_tenant_bindings 无对应记录
- **THEN** codegen Stage 4 返回结构化错误 `{"error":"binding_missing","env":"prod","tenant":"corp-a","layer":"Application","hint":"请管理员配置 binding"}`，工单进入 `blocked-policy`

#### Scenario: vpc_stack_id 必须 Global 层
- **WHEN** 提交 binding 时 vpc_stack_id 引用 Middleware 层 stack（如 rds-orders-prod）
- **THEN** 平台校验 stack.layer_logical_id ≠ Global 时返回 400，拒绝 binding 创建

#### Scenario: vpc_stack_id outputs 校验
- **WHEN** binding 引用的 Global 层 vpc stack 的 outputs 不含 `vpc_id` 或 `vswitch_ids`
- **THEN** 平台校验失败，提示"vpc stack outputs must contain vpc_id and vswitch_ids"

#### Scenario: account-per-env override 校验
- **WHEN** tenant.isolation_level=account-per-env 但 binding.override_cloud_account_id 为空
- **THEN** 平台返回 400 + `"override_cloud_account_id required for account-per-env mode"`

#### Scenario: account-per-env override ≠ env 默认账号
- **WHEN** binding.override_cloud_account_id 与 environments.cloud_account_id 相同
- **THEN** 平台返回 400 + `"override_cloud_account_id must differ from environments.cloud_account_id"`

#### Scenario: 多 layer 共享 VPC
- **WHEN** 同 (env=prod, tenant=corp-a) 的 Middleware binding 和 Application binding 引用同一 vpc_stack_id
- **THEN** 平台允许（共一个 VPC），codegen 两层都注入同一 vpc_id

### Requirement: env 维度授权（team_cloud_grants.env_scope_json）
平台 SHALL 在 `team_cloud_grants` 表新增 `env_scope_json` 字段。空数组 `[]` 表示全 env；非空（如 `["prod","staging"]`）限定 env_logical_id 列表。申请页"可选云账号+env+层"由 `team_cloud_grants WHERE team_id=? AND env_scope ∋ selected_env AND allowed_layers ∋ selected_layer` 驱动。

#### Scenario: 全 env 授权
- **WHEN** team_cloud_grants(team=DBA, cloud_account=alicloud-prod, env_scope_json=[])
- **THEN** DBA 团队在 dev/staging/prod 所有 env 都可申请该云账号资源

#### Scenario: 限定 prod 授权
- **WHEN** team_cloud_grants(team=order-service, cloud_account=alicloud-prod, env_scope_json=["prod"]) + 团队成员申请 env=dev
- **THEN** 平台返回 403 + `"team order-service not authorized for env=dev on cloud_account alicloud-prod"`

### Requirement: 创建顺序约束
平台 SHALL 强制创建顺序：environments → tenants → environment_tenant_bindings。binding 引用的 env_id/tenant_id/vpc_stack_id MUST 已存在。

#### Scenario: binding 引用不存在的 env
- **WHEN** 提交 binding.env_id 指向不存在的 environments 记录
- **THEN** 平台返回 400 + `"env_id not found"`

#### Scenario: binding 引用不存在的 vpc stack
- **WHEN** 提交 binding.vpc_stack_id 指向不存在或已 destroyed 的 stack
- **THEN** 平台返回 400 + `"vpc_stack_id not found or destroyed"`

### Requirement: 跨租户网络治理分离
平台 SHALL 把跨租户网络互通（CEN / VPC Peering / Transit Gateway）作为独立的 Global 层 stack 治理，MUST NOT 把路由策略塞进 environment_tenant_bindings 表。跨租户访问申请走 catalog + 审批标准流程。

#### Scenario: 跨租户访问走 catalog
- **WHEN** corp-a 业务团队需要访问 DBA 团队管理的共享 RDS
- **THEN** 走 catalog 项"cross-tenant-rds-access"，绑定 cross-layer 依赖，审批通过后 codegen 注入 remote_state data source + CEN 路由

### Requirement: lifecycle（freeze/deprecate）
平台 SHALL 支持 environments/tenants/bindings 的 `status` 字段：`active` / `frozen`（迁移期冻结）/ `deprecated`（标记下线）。frozen 时新工单拒绝，已有 stack 静默继续运行；deprecated 时禁止新建 binding，存量 stack 走 sunset 流程（D26 §3）。

#### Scenario: freeze env 阻断新工单
- **WHEN** 管理员标记 environments.status=frozen（如重大事故应急）
- **THEN** 所有新工单引用此 env_id 时返回 409 + `"env frozen, contact admin"`

#### Scenario: deprecate tenant 走 sunset
- **WHEN** 管理员标记 tenants.status=deprecated
- **THEN** 该 tenant 不允许新建 environment_tenant_bindings，已有 stack 走 D26 sunset 流程
