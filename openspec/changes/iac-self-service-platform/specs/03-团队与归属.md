# 03-团队与归属（tenancy-model）

能力 ID：`tenancy-model`
覆盖：团队 / 项目组 / 部署单元（bundle）的组织模型与资源归属，对应"网络运维 / DBA / 中间件 / 业务项目组"的多团队分层治理。

## ADDED Requirements

### Requirement: 团队模型
平台 SHALL 维护团队实体，每类基础设施资源归属到固定治理团队：全局网络与集群 → `平台运维`，RDS/Redis → `DBA`，Kafka/RabbitMQ → `中间件`，应用计算资源 → 业务 `项目组`。

#### Scenario: 资源归属固定团队
- **WHEN** 一台 RDS 被创建
- **THEN** 其归属团队固定为 `DBA`，即使由业务项目组发起申请，资源治理权仍在 DBA

### Requirement: 项目组与部署单元（bundle，可选）
平台 SHALL 支持"项目组"实体，一个项目组拥有零个或多个"部署单元（bundle）"；bundle 是一组 stack 的逻辑分组，对应一个独立的资源集合与状态边界集合。**bundle 可选**——小业务部门在 D29 layer-first 拓扑下直接 `application/<tenant>/<team>/<component>-<env>`（无 bundle），大业务部门多产品线用 `application/<tenant>/<team>/<bundle>/<component>-<env>` 分组；元数据 `stacks.bundle_id` NULL 表示无 bundle。

#### Scenario: 业务团队 A 的两个部署单元
- **WHEN** 业务团队 A（大业务部门）有"订单"与"用户"两套服务
- **THEN** 平台支持为其创建两个 bundle：`team-a/orders`、`team-a/users`，各自包含独立的 stack 集合与状态隔离

#### Scenario: 小业务部门无 bundle
- **WHEN** 业务团队 B（小业务部门，资源少）直接申请 ECS
- **THEN** stack 路径为 `application/platform-default/team-b/ecs-prod`（无 bundle 层），与有 bundle 的 `application/platform-default/team-a/orders/ecs-prod` 两种路径平台都识别

### Requirement: 跨团队资源访问
平台 SHALL 支持跨团队"申请访问"语义：业务项目组可申请由 DBA / 中间件团队治理的资源的使用权（如数据库账号、Kafka Topic），而资源本体治理权不变。

#### Scenario: 业务团队申请 RDS 账号
- **WHEN** 业务团队 A 在 `rds-orders-prod`（归属 DBA）上申请只读账号
- **THEN** 平台生成"账号申请"工单流转到 DBA 审批，审批通过后生成对应 Terraform 代码并执行；RDS 实例治理权仍属 DBA

### Requirement: bundle 与 stack 映射
平台 SHALL 把每个 bundle 映射到一个目录根，其下的每个原子组件对应一个 Terramate stack；bundle 是平台层概念，Terramate 本身无感知。

#### Scenario: bundle 内多 stack
- **WHEN** bundle `team-a/orders` 包含 ECS、SLB、RDS 账号三个组件
- **THEN** 平台在 bundle 根下生成 3 个 stack 目录，各自独立状态文件；执行时可按 bundle 整体编排或按 stack 单独操作

### Requirement: 基于团队的 RBAC
平台 SHALL 按团队 / 项目组 / bundle / 资源类型实施 RBAC，区分"可申请"、"可审批"、"可执行"、"可查看"四类动作。

#### Scenario: 业务团队无权直接改 VPC
- **WHEN** 业务团队用户尝试修改 `vpc-global-prod`
- **THEN** 平台拒绝，错误信息指向"归属平台运维团队，需走变更申请"
