# 22-平台运营指标（platform-operations-metrics）

能力 ID：`platform-operations-metrics`

覆盖：平台产品化运营指标、catalog health、scorecard、DORA/SPACE、自助率、失败原因分析。

## ADDED Requirements

### Requirement: 平台运营指标
平台 SHALL 采集并展示 self-service ratio、ticket deflection、successful run rate、mean approval wait、time to provision、reconcile debt。

#### Scenario: 自助率看板
- **WHEN** 平台运营查看月度看板
- **THEN** 可看到自助完成申请数、人工工单数、自助率趋势和主要阻塞原因

### Requirement: 失败原因结构化
每个 failed run SHALL 写入结构化失败原因，至少包含 `user_input`、`policy_denied`、`cloud_quota`、`cloud_api`、`toolchain`、`state_backend`、`platform_bug`、`manual_required`。

#### Scenario: 失败原因 TopN
- **WHEN** 某 catalog item 连续失败
- **THEN** 平台可按失败类别聚合 TopN，并输出 owner 可执行的治理建议

### Requirement: Catalog Health
平台 SHALL 为每个 catalog item 计算 health，覆盖 usage、reliability、governance、cost、version、ownership。

#### Scenario: 不健康目录项
- **WHEN** 某 catalog item apply 成功率低于阈值
- **THEN** 平台将其标记为需治理，并在服务目录中降低推荐等级

### Requirement: Scorecard
平台 SHALL 提供服务成熟度 scorecard，支持 L0 到 L4 分级，并展示到目录详情页和平台运营看板。

#### Scenario: Golden catalog item
- **WHEN** catalog item 分数达到 90 且连续 30 天成功率达标
- **THEN** 平台标记为 golden path，可推荐给新团队使用

### Requirement: 运营复盘
平台 SHALL 支持周/月/季度复盘输出，覆盖 run health、approval health、catalog usage、drift health、cost guardrail、platform SLO。

#### Scenario: 月度复盘
- **WHEN** 平台团队生成月度报告
- **THEN** 报告包含趋势、异常 TopN、治理动作和下月目标
