### 2.1 控制面与事实源边界

| 数据类型 | 事实源 | 说明 |
|----------|--------|------|
| 工单、审批、授权、参数来源 | 元数据 DB | 控制面事实源，所有状态迁移必须写 `request_events` 和 `audit_logs` |
| 生成代码与 stack 定义 | Git pinned commit | 代码事实源，Executor 只能检出 `requests.pinned_commit` |
| 资源真实状态 | Terraform state | 执行面事实源，CMDB 不复制 state 全文 |
| 资源查询与归属 | CMDB index | 从 state/cloud inventory 重建，失败进入 reconcile，不反向覆盖 state |
| 成本实际值 | 云账单 | Infracost 只用于申请时估算和审批提示 |

### 2.2 主链路与旁路治理

主链路只承载不可跳过的 IaC 变更控制：`Catalog → Request → Codegen → Git Commit → Plan Artifact → Approval → Apply → Reconcile`。CMDB、FinOps、通知、AI、孤儿检测、StateMover 均为旁路能力，除安全策略、凭据、state 健康、plan artifact 校验外，不得阻塞已获准的 apply；旁路失败必须进入 `reconcile-pending` 或 `manual_intervention_tasks`。

### 3.1 异步断点处理

| 断点 | 状态 | 处理 |
|------|------|------|
| codegen 写临时目录失败 | `failed-retryable` | 丢弃临时目录，不污染 worktree |
| git commit 成功但 DB 写 `pinned_commit` 失败 | `failed-retryable` | reconcile job 通过 commit marker 找回或回滚孤儿 commit |
| plan 上传成功但 artifact row 写入失败 | `failed-retryable` | 对象存储扫描补偿，孤儿 artifact 超时清理 |
| plan 产物过期或工具链 hash 不一致 | `expired` | 强制重 plan + 重 pre-apply 审批 |
| apply 中断 | `waiting-manual` | 不自动重试，生成 `manual_intervention_tasks` 做 state 检查 |
| apply 成功但 CMDB/通知/FinOps 失败 | `reconcile-pending` | 不判 apply 失败，outbox 重放 + reconcile |

## 4. 部署拓扑

- **平台服务**：`cmd/platform` 二进制，无状态（状态全在元数据 DB + 工作仓库 + 远程 state），可水平扩展；漂移检测器可独立部署为单独 worker。
- **元数据 DB**：PostgreSQL（推荐）或 MySQL，带主从。
- **工作仓库**：每个执行节点本地 `git worktree` 池，远端为 bare git 仓库（自建 Gitea 或托管）。
- **State Backend**：MinIO（自建 S3 兼容）+ DynamoDB 兼容锁（或 etcd 锁适配）。
- **前端**：静态构建，CDN/Nginx 托管。
