# 20-安全与合规证据链

> 企业级平台不能只说“有审计”，必须能证明审计未被篡改、审批可追溯、紧急操作有补偿、敏感数据未泄漏。

## 1. 证据链目标

| 问题 | 证据 |
|------|------|
| 谁做了什么 | `audit_logs` + `request_events` |
| 为什么允许 | approval decision + OPA/RunHook policy summary |
| 影响了什么 | plan artifact + apply log + CMDB resource index |
| 是否被篡改 | HMAC chain + immutable object storage |
| 异常如何闭环 | incidents + runbook executions + manual tasks |

## 2. 审计完整性

每条高价值审计日志增加：

| 字段 | 说明 |
|------|------|
| `prev_hash` | 前一条同 scope 审计 hash |
| `entry_hash` | 当前条 canonical JSON 的 HMAC |
| `signing_key_id` | HMAC key 版本 |
| `sealed_at` | seal 时间 |

审计日志写入后不可更新；修正只能追加 correction event。

## 3. 不可变存储

以下 artifact 必须进入对象存储并启用保留策略：

- plan 二进制。
- plan JSON summary。
- apply 日志。
- approval snapshot。
- OPA/RunHook 结果。
- break-glass 录屏或命令记录。

### 3.1 保留周期与 Legal Hold

| 证据类型 | 默认保留 | 高危/生产保留 | 说明 |
|----------|----------|---------------|------|
| plan binary / plan JSON | 30 天 | 90 天 | 过期后保留 hash 与摘要 |
| apply 日志 | 90 天 | 180 天 | 事故相关转入 incident evidence |
| approval snapshot | 180 天 | 1 年 | 支撑审计抽查 |
| OPA / RunHook 结果 | 180 天 | 1 年 | 证明“为什么允许/拒绝” |
| break-glass 录屏/命令记录 | 1 年 | legal hold 解除前保留 | P0/P1 事故必须保留 |
| audit HMAC chain metadata | 3 年 | 3 年以上按合规要求 | 不含敏感明文 |

Legal hold 规则：

- 进入 incident、审计调查、合规抽查的证据包必须标记 `legal_hold=true`。
- legal hold 期间禁止 GC，即使超过默认保留周期。
- 解除 legal hold 必须双人审批并写审计。

### 3.2 HMAC Key 生命周期

| 项 | 规则 |
|----|------|
| key rotation | 默认每 90 天轮换 signing key |
| key storage | 存 KMS/Vault，DB 只保存 `signing_key_id` |
| verify old chain | 旧 key 只读保留，用于校验历史链，不再签新日志 |
| key compromise | 标记 affected window，冻结相关证据包，触发 incident |
| chain break | 立即生成 P1 incident，阻断审计导出为“可信通过”，只允许导出“异常证据包” |

## 4. Break-glass

| 阶段 | 要求 |
|------|------|
| 触发 | 仅 P0/P1 事故可触发，必须填写 incident id |
| 授权 | 双人持有或双人确认 |
| 执行 | 全程录屏或命令记录，所有命令写审计 |
| 补审批 | 24h 内 retroactive approval |
| 复盘 | 必须产生 incident report 和改进任务 |

break-glass 不等于绕过治理，而是把治理从事前审批切到事后强证据补偿。

## 5. State 与 Secret 审计

| 操作 | 要求 |
|------|------|
| state 下载 | 必须审批或 break-glass，写审计 |
| state restore | 必须演练过，双人审批 |
| secret 读取 | 只允许 Executor 或 bootstrap 流程，禁止 Web 直接展示 |
| credential rotation | 写入 rotation event，关联 affected requests |

## 6. 合规证据包

平台应能按 request / stack / 时间窗口导出证据包：

- request 基本信息。
- actor 和身份源。
- approval 轨迹。
- policy summary。
- plan artifact hash。
- apply executor run。
- CMDB resource index。
- cost estimate 和实际账单关联。
- audit HMAC chain 校验结果。

## 7. 演练要求

| 演练 | 频率 |
|------|------|
| state restore drill | 每季度 |
| DB restore drill | 每季度 |
| break-glass drill | 每半年 |
| OIDC JWKS rotation drill | 每半年 |
| provider mirror outage drill | 每半年 |
