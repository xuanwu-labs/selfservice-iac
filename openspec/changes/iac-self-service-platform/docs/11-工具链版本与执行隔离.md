# 11-工具链版本与执行隔离

> 对应 design `D12/D13/D15/D20`、spec `specs/11-工具链版本管理`。重点回应 Q2（版本管理 + Web 配置 vs 配置文件）与 Q4（执行隔离 / 是否必须对接 K8s）。

## 1. 三层版本管理

| 层 | 工具 | 锁定方式 | 版本选择 | 多版本共存 |
|----|------|----------|----------|------------|
| Terramate | 平台 exec | 全局配置（可灰度多版本） | 适配器按配置选 | 平台缓存多版本二进制 |
| Terraform/OpenTofu | [tenv](https://github.com/tofuutils/tenv) | per-stack `required_version` | tenv 解析 | ✅（1.5/1.9 共存） |
| Provider | `.terraform.lock.hcl` | 锁定 + registry mirror | init 时按 lock | ✅ |

**业界对照**：借鉴 Spacelift 的自定义 worker image + init script 模式——工具链进镜像，版本变更 = 新镜像灰度。

## 2. Worker 镜像（固化工具链）

```dockerfile
# server/images/tm-worker.Dockerfile
FROM gcr.io/distroless/static-debian12:nonroot  # 或 debian-slim 带 tenv
# 预装
COPY terramate_v0.17.1 /usr/local/bin/terramate
RUN tenv install terraform 1.9.5 && tenv install opentofu 1.8.6
# provider mirror 缓存
COPY provider-mirror /opt/provider-mirror
# 策略/成本工具
COPY opa /usr/local/bin/opa && COPY infracost /usr/local/bin/infracost
# git（go-git 运行时 + 命令行）
RUN apk add --no-cache git openssh-client
```
- 镜像 tag 与三层版本对齐：`tm-worker:tm0.17-tf1.9-20260615`。
- CI 构建 + 灰度（dev→staging→prod）+ 旧镜像保留回滚。

## 3. 执行运行时：可插拔 Executor 四模式 + 镜像构建管线（D20，回应"是否必须对接 K8s / 镜像仓库"）

**结论：K8s 与镜像仓库均非必需。** 平台定义 `Executor` 接口抽象沙箱执行，四模式可插拔；**process 为零依赖默认**（无容器/镜像/仓库），仅当需强隔离 / 多租 / 水平扩展才上容器或 K8s。

### 3.1 Executor 接口

```go
// server/core/executor/executor.go
type Executor interface {
    // Run 在隔离沙箱内执行 cmd；process 模式 Image 可空（用预装工具链）
    Run(ctx context.Context, spec RunSpec) (RunResult, error)
    Name() string  // "process" | "container" | "kubernetes" | "remote"
}

type RunSpec struct {
    Worktree   string            // host 侧 worktree 路径（D4）
    Image      string            // worker 镜像 tag（D12）；process 模式可空
    Command    []string          // terramate run ... 的完整命令
    Env        map[string]string // 含 secret 占位符解析后的运行期注入
    Resources  ResourceLimits    // CPU/Mem/Disk
    Network    NetworkPolicy     // egress 白名单 / 断网
    Timeout    time.Duration
    LogSink    func(line string) // 流式回传 request_events
}
type RunResult struct{ ExitCode int; Stdout, Stderr string }
```

编排引擎与漂移检测（docs/13）只依赖接口，不感知进程/容器/Pod/SSH 差异；`TerramateAdapter`（封装 terramate 命令语义）与 `Executor`（封装运行时沙箱）正交解耦。**漂移只读 plan 也走同一 Executor（同一 worktree / 工具链 / 隔离契约）。**

### 3.2 四模式对照

| 维度 | process（默认） | container | kubernetes | remote |
|------|-----------------|-----------|------------|--------|
| 实现 | `ProcessExecutor` | `ContainerExecutor` | `K8sExecutor` | `RemoteNodeExecutor` |
| 运行时 | 子进程 + cgroups v2 + netns | 宿主机 docker/podman | K8s Job/Pod | SSH + 远程进程/容器 |
| 沙箱单位 | worktree 目录 + 子进程 | 每工单一容器 | 每工单一 Job（namespace） | 每工单远程进程/容器 |
| 工具链来源 | **节点预装**（installer） | worker 镜像 | worker 镜像 | 节点预装或镜像（per-node） |
| 需镜像仓库 | **否** | 是（镜像需在本地） | 是（仓库可达） | per-node |
| 水平扩展 | ✗（单节点） | ✗（单节点） | ✓（集群） | ✓（节点池） |
| 额外基础设施 | **无** | 本地 docker | K8s 集群 | SSH 主机池 |
| 隔离强度 | 中（cgroups+netns） | 强（容器） | 强（Pod） | per-node |
| 适用 | MVP / dev / 内网 / 小团队 / CI | 单节点强隔离 | 企业 K8s / 高并发 | 离线 / 裸机 / 复用存量 |

### 3.3 镜像构建管线（仅 container / kubernetes / remote(container) 需要）

```
Web "保存工具链版本"（terramate + tf/tofu + providers + opa + infracost pin）
   → ImageBuilder 渲染 Dockerfile 模板（§2 的 Dockerfile 参数化）
   → 异步构建（平台内置 docker API / 构建节点，或外部 CI webhook）
   → tag = tm-worker:tm0.17-tf1.9-20260615
   → push → 可插拔 ImageRegistry 适配器
   → 灰度（dev→staging→prod）+ 旧镜像保留回滚
```

- `BuildDriver` 可插拔（D22）：`docker`=本地/构建节点 docker daemon；`buildah`=daemonless 进程（无需 daemon）；`kaniko`=K8s 内无 daemon 构建。**构建本身可进程化**，不强制宿主有 docker。默认按 mode 选（container→docker/buildah，kubernetes→kaniko）。
- `ImageRegistry` 适配器：Harbor / 阿里云 ACR / AWS ECR / Azure ACR / Docker Registry / **内嵌本地 registry**（单节点零外部依赖）/ **文件中转**（离线：构建机导出 tar，目标节点 import）。
- **process 模式完全不触发镜像构建**：工具链由 `server/core/installer`（D22 §6）按基线自动 reconcile 节点（mirror 下载→checksum→装+symlink+manifest），离线由 admin 手动投放。
- 双路径对应业界两派（见 §3.6），平台都支持，按部署形态选。

### 3.4 选择与切换

- 配置位置：`adapters_config.executor`（DB，D15 易变配置）——`mode` + `image.registry/image.repo/build_node` + 模式专属配置（kubernetes：kubeconfig/namespace；remote：节点池清单 + SSH 凭据 + per-node type；container：runtime=docker|podman；process：节点清单 + 预装工具链版本基线）。
- 切换：Web 改 `mode` → 热加载 → 新工单按新模式调度，存量在跑工单不中断 → 审计。
- MVP 约束：每个平台实例仅一个活跃 `mode`（按 tenant/layer 分流到不同 mode 为后续扩展）。

### 3.5 统一契约（四模式都必须满足）

1. 挂载该工单 git worktree（docs/10）到沙箱
2. 工具链版本与 stack `required_version`/provider 兼容（§5 校验）
3. CPU/内存/磁盘限制 + 超时
4. 网络出口策略（egress 白名单 / 关键 stack 断网，防数据外泄）
5. 退出码捕获 + stdout/stderr 流式回传 `request_events`
6. 同一工单在四模式下退出码、日志格式、worktree 路径、工具链版本一致（可互换不改语义）

### 3.6 业界对照（两派共识）

- **容器派**（Spacelift / Env0）：worker image + registry，强隔离，强制镜像依赖。
- **进程派**（Atlantis ~8k 星 / Jenkins-terraform）：预装工具链 + 目录 + 进程隔离，**无 registry**，广泛落地于 GitOps。
- 平台 D20：**两派都支持**——process 为零依赖默认（进程派），container/kubernetes 为强隔离/扩展（容器派），remote 覆盖离线裸机。不强制任何一种依赖。

### 3.7 关键时序：工单执行（模式无关，plan/apply 解耦 D21）

```
[plan] Orchestrator → 兼容校验(§5) → Executor.Run(terramate run ... plan)
   → [process:子进程 | container:docker run | k8s:Job | remote:ssh exec]
   → terraform plan -out=/work/plan.tfplan + plan JSON
   → 解析输出 + Infracost 成本 + 漂移校验
   → 上传 plan.tfplan 到对象存储 s3://tm-plans/<req_id>/plan.tfplan
   → 写 artifacts(kind=plan_binary, ref, sha256, size_bytes)  ← D21 plan 产物链路锚点
   → ★销毁沙箱★
[审批] 状态机 pending-approval（Gate2 执行确认，UI 展示 plan diff + 成本 + 漂移状态）→ 审批人决策（不依赖存活沙箱）
[apply] 审批通过 → 新沙箱 Executor 检出 pinned_commit
   → 按 request_id 查最新 artifacts(kind=plan_binary) 下载 plan.tfplan
   → sha256 校验（防篡改/防损坏）
   → terraform apply "plan.tfplan"（不重 plan，保证审批时见即所得）
   → 回写 → 销毁
漂移检测（异步）：DriftScheduler → Executor.Run(只读 plan -detailed-exitcode) → 解析 JSON → drift_record（同一 Executor/沙箱）
```

**plan 产物存储契约**（D21 关键）：
- **存储位置**：独立对象存储 bucket（如 `s3://tm-plans/`），与 state backend（`s3://tm-state/`）分离；plan.tfplan 是二进制不可读，需要原 workspace 上下文才能 apply，故必须配 `pinned_commit` 一起用。
- **生命周期**：apply 成功后保留 N 天（默认 30）供审计/回查，过期 GC；apply 失败保留更久。
- **完整性**：上传时算 sha256 写 `artifacts.sha256`，apply 下载后强制比对，不一致直接 abort（防中间人/存储损坏）。
- **跨沙箱**：plan 阶段沙箱销毁后，apply 阶段是全新沙箱（不同节点都可能），所以 plan 产物**必须**进对象存储，不能放 worktree（worktree 随沙箱销毁）。

## 4. Registry Mirror（私有 provider）

```
# terraform.rc / CLI config
provider_installation {
  filesystem_mirror { path = "/opt/provider-mirror" }
  direct { exclude = ["corp/*"] }   # corp/* 强制走 mirror
}
```
- 自建 Terraform Registry 兼容服务（或文件系统 mirror）。
- 公网 provider 可走 mirror 缓存（离线/加速），私有 provider 强制 mirror。

## 5. 版本兼容校验（三时机，D22）

```go
// 执行前校验（时机③）
func validateCompatibility(stack Stack, sandbox Sandbox) error {
    // sandbox 或为镜像（解 manifest）或为预装节点（取 toolchain_manifest）
    tc := sandbox.Toolchain()  // {Terramate, TF, Providers...}
    if !semver.Match(tc.TF, stack.RequiredVersion)  { return ErrIncompatible("切到 tf"+stack.RequiredVersion) }
    for _, p := range stack.Providers {
        if !tc.HasProvider(p) { return ErrProviderMissing("装/选含 "+p) }
    }
    return nil
}
```

| 时机 | 触发 | 校验内容 | 失败处理 |
|------|------|----------|----------|
| ①注册时 | 模块注册 | 提取 `required_version`/provider 约束，校验存在满足的 profile | 标 `validation-failed`，提示约束 |
| ②catalog 发布 | 目录项发布 | 声明目标工具链 profile，校验与已注册镜像/预装基线一致 | 阻断发布，提示缺版本 |
| ③执行前 | orchestrator 调 Executor 前 | sandbox（镜像 manifest / 节点 `toolchain_manifest`）满足 stack 约束 | 阻断执行，给可操作提示 |

**镜像 sandbox**：解 image tag 或 registry manifest 取内置版本清单。**预装 sandbox**：读节点 `toolchain_manifest`（installer 维护的真相源）。

不兼容 → 阻断并给可操作提示（"切到镜像 X" / "节点装 provider Y"）。原型"版本与工具链"页已体现多镜像选择 + executor 模式。

## 6. 节点工具链安装（process 模式，D22）

```
Web 设工具链基线（D15 存 DB：terramate + tf/tofu + providers 版本）
  → installer reconcile 各执行节点：
      从平台 mirror/制品仓下载 → checksum 校验
      → 装到 /opt/tm/toolchains/<ver>/ + symlink active
      → 写 toolchain_manifest（节点级真相源，DB + 节点双写）
[离线兜底] admin 投放二进制到 /opt/tm/toolchains/incoming/
      → installer 仅注册进 manifest（不下载），校验仍工作
```

- **自动优先**：默认 installer 自动 reconcile，运维零负担，版本升级 = 改基线 + reconcile。
- **手动兜底**：air-gap 无制品仓可达时，admin 投放二进制，installer 注册。
- `toolchain_manifest` 是校验（§5 时机③）与可见性的**真相源**。

## 6. 双层配置（D15）

| 配置类 | 存储 | 变更方式 | 例子 |
|--------|------|----------|------|
| 易变业务 | 元数据 DB | Web 改、热加载、审计 | 适配器装配、身份源、RBAC、审批 DSL、目录项、漂移调度 |
| 工具链版本 | worker 镜像 | CI 构建、灰度 | terramate/tf/provider 版本组合 |

**结论**（回应"Web 配置还是配置文件"）：**两者结合**——业务配置 Web 可改（启动从 DB 加载），工具链版本走镜像（启动时镜像已固化）。平台启动 = 加载 DB 配置 + 调度预置镜像。
