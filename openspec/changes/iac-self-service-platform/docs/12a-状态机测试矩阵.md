# 12a-状态机测试矩阵

> 本文把 RequestLifecycle 从设计语义转成工程测试矩阵。所有 orchestrator 实现和 e2e 必须引用这些测试 ID。

## 1. 测试原则

- 主链路和异常链路同等重要。
- 每个状态迁移必须验证 `request_events`、`audit_logs`、`version` 乐观锁。
- 涉及外部副作用的测试必须验证 `outbox_events` 或 `reconcile_jobs`。
- apply 中断和 state 不确定不得自动重试。

## 2. 主链路测试

| ID | 场景 | 初始状态 | 事件 | 期望状态 | 核心断言 |
|----|------|----------|------|----------|----------|
| RLC-001 | 创建申请 | none | submit | `submitted` | 返回 `request_id` 和 `correlation_id` |
| RLC-002 | codegen 成功 | `submitted` | start_generate | `generating` | 写 `request_events` |
| RLC-003 | commit 锚定 | `generating` | codegen_done | `planning` 或 `pending-admission` | `pinned_commit` 非空 |
| RLC-004 | plan 成功 | `planning` | plan_done | `plan-ready` | 写 plan artifact，含 sha256 与 expires_at |
| RLC-004b | 启动执行确认审批 | `plan-ready` | approval_started | `pending-approval` | 校验 artifact sha256/toolchain/provider lock 后再创建 approval run |
| RLC-005 | 审批通过 | `pending-approval` | approval_pass | `applying` | 新沙箱检出同一 `pinned_commit` |
| RLC-006 | apply 成功 | `applying` | apply_success | `reconciling` | 写 executor run 和 outbox |
| RLC-007 | reconcile 成功 | `reconciling` | reconcile_success | `succeeded` | CMDB index upsert 成功 |

## 3. 异常与补偿测试

| ID | 场景 | 初始状态 | 故障 | 期望状态 | 核心断言 |
|----|------|----------|------|----------|----------|
| RLC-101 | codegen 失败 | `generating` | template error | `failed-retryable` | 临时目录清理，可重跑 |
| RLC-102 | git commit 成功但 DB 失败 | `generating` | DB write failed | `failed-retryable` | reconcile 可通过 commit marker 找回 |
| RLC-103 | plan 上传成功但 artifact row 失败 | `planning` | DB write failed | `failed-retryable` | 对象存储扫描补偿 |
| RLC-104 | plan artifact 过期 | `pending-approval` | TTL expired | `expired` | 旧 artifact 标 `expired` |
| RLC-105 | toolchain hash 不一致 | `applying` | hash mismatch | `expired` | 阻断 apply，要求重 plan |
| RLC-106 | 审批驳回 | `pending-approval` | reject | `rejected` | 保留 plan artifact 供审计 |
| RLC-107 | 审批超时升级 | `pending-approval` | timeout | `pending-approval` 或 `rejected` | escalation 写入 approval 子状态；request status 不新增 `escalation` |
| RLC-108 | apply 瞬时失败 | `applying` | cloud 429 | `failed-retryable` | 可受控重试 |
| RLC-109 | apply 中断 | `applying` | executor lost | `waiting-manual` | 生成 `manual_intervention_tasks` |
| RLC-110 | apply 成功但 CMDB 失败 | `reconciling` | ingester failed | `reconcile-pending` | 不回滚资源，outbox dead-letter |
| RLC-111 | state backend 不健康 | `planning` | circuit open | `blocked-state-health` | 后端恢复后可续跑 |
| RLC-112 | drift 暂停 | any active | drift overload | `paused-drift` | 禁新申请，已有 apply 不被误回滚 |
| RLC-113 | saved-plan apply 命令契约 | `applying` | apply_start | `applying` | 必须通过 TerramateAdapter.RunApplySavedPlan，禁止 Orchestrator 直接调用 terraform |
| RLC-114 | break-glass 执行 | `applying` | emergency_start | `applying` | `emergency_runs.status=active`，request status 不新增 `break-glass-applying` |
| RLC-115 | dependency seed 缺失 | `generating` | dependency_missing | `blocked-policy` | 生成 `dependency_seed_missing` 错误，阻断首个业务申请 |

## 4. 幂等测试

| ID | 场景 | 输入 | 期望 |
|----|------|------|------|
| IDEMP-001 | Web 双击提交 | 同 actor + catalog + form_hash | 返回同一 request |
| IDEMP-002 | CI 重试相同 YAML | 同 pipeline + commit + catalog + form_hash | 返回同一 request |
| IDEMP-003 | CI 同 commit 改参数 | form_hash 改变 | 创建新 request |
| IDEMP-004 | 审批重复提交 | 同 run + node + approver + decision | 后续请求返回已决策 |
| IDEMP-005 | outbox 重放 | 同 event id | 外部副作用只执行一次或幂等 upsert |

## 5. 并发测试

| ID | 场景 | 期望 |
|----|------|------|
| CONC-001 | 两个 request 同时 plan 同一 stack | 一个获得 stack lock，另一个 409 或排队 |
| CONC-002 | 两个 apply 竞争同一 state key | 后者等待或失败，不绕过 state lock |
| CONC-003 | 乐观锁冲突 | 失败方重读状态后再决策 |
| CONC-004 | outbox worker 并发投递同事件 | 只有一个 worker 成功 claim |

## 6. 验收

Phase 1 必须通过：RLC-001 到 RLC-006、RLC-004b、RLC-101 到 RLC-115、IDEMP-001 到 IDEMP-005、CONC-001 到 CONC-004。

Phase 2 增加：`pending-admission`、双门禁、drift remediation、CI gate、OIDC credential expiry 的状态机测试。
