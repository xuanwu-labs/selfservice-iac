# 18-平台运营与指标

> 商业级平台必须作为产品运营，而不是一次性项目交付。本文定义平台成功指标、运营看板和复盘机制。

## 1. 北极星指标

| 指标 | 定义 | 目标 |
|------|------|------|
| Self-service Ratio | 自助完成的 IaC 申请 / 总 IaC 申请 | Phase 1 ≥ 30%，Phase 2 ≥ 60% |
| Ticket Deflection | 被平台替代的人工工单数 | 持续上升 |
| Successful Run Rate | 成功 run / 总 run | Phase 1 ≥ 95% |
| Mean Approval Wait | 审批等待中位数 | dev/staging < 2h，prod < 24h |
| Time To Provision | request submitted 到 apply succeeded | 标准资源 < 30min |
| Reconcile Debt | `reconcile-pending` 超 SLA 数 | 趋近 0 |

## 2. DORA / SPACE 映射

| 框架 | 平台映射 |
|------|----------|
| Deployment Frequency | 每周成功 apply 次数 |
| Lead Time | request 创建到资源可用时间 |
| Change Failure Rate | failed / waiting-manual / rollback run 比率 |
| MTTR | 平台侧故障恢复时间 |
| SPACE Satisfaction | 平台 NPS、审批体验、失败原因可理解度 |
| SPACE Efficiency | 自助率、平均填写时长、重复提交率 |

## 3. 运营看板

| 看板 | 内容 |
|------|------|
| Run Health | 成功率、失败原因 TopN、平均 plan/apply 时长 |
| Approval Health | 队列长度、超时、升级、团队审批瓶颈 |
| Catalog Usage | 热门目录项、无人使用目录项、失败率高目录项 |
| Drift Health | 覆盖率、open drift、连续漂移 stack |
| Cost Guardrail | 预估超预算次数、实际账单偏差、未归集成本 |
| Platform SLO | API 可用性、Executor 队列、outbox backlog、reconcile debt |

## 4. 失败原因分类

所有 failed run 必须归类：

| 类别 | 示例 |
|------|------|
| `user_input` | 表单值类型错误、缺必填 |
| `policy_denied` | OPA 或 Run Hooks 阻断 |
| `cloud_quota` | 云配额不足 |
| `cloud_api` | 云 API 限流/不可用 |
| `toolchain` | provider 下载失败、版本不兼容 |
| `state_backend` | state lock 或 backend 不健康 |
| `platform_bug` | codegen 或 orchestrator bug |
| `manual_required` | state 不确定，需要人工介入 |

## 5. 复盘节奏

| 周期 | 动作 |
|------|------|
| 每周 | 查看 failed run TopN、审批超时、reconcile debt |
| 每月 | 复盘自助率、catalog 健康、drift 覆盖、成本偏差 |
| 每季度 | 平台 NPS、DORA/SPACE 趋势、Phase 规划调整 |

## 6. 运营验收

Phase 1 上线不只要求功能通过，还必须具备：

- Run Health 看板。
- Approval Health 看板。
- Catalog Usage 看板。
- failed run reason 结构化字段。
- 平台 NPS 或满意度收集入口。
- 每月运营复盘模板。

## 7. Phase 1 运营边界

Phase 1 的运营目标是证明 golden path 可用，不追求完整商业平台指标覆盖。

| 能力 | Phase 1 口径 |
|------|--------------|
| Run Health | 必须有 |
| Approval Health | 必须有 |
| Catalog Usage | 必须有 |
| Drift Health | 只覆盖 golden path stack |
| Cost Guardrail | 只做 Infracost 估算和预算提示，不做账单核销 |
| Scorecard | 可展示，但 `confidence` 低时不得自动下架 |
| DORA/SPACE | 可采集基础数据，不作为考核指标 |

运营原则：

- Phase 1 看板只服务发现问题，不服务自动治理。
- 自动阻断必须来自安全、状态一致性、权限和审批，不来自低可信度运营分数。
- 平台推广指标不得压过主链路稳定性指标。
